# Closed, minimal allowlist of engine `stage` tokens the privacy-safe diagnostic
# may emit. Membership is EXACT (full-string), never prefix or charset — a
# prefix admits a value-carrying stage (an IP/hostname is [a-z0-9_.]) and a
# charset guard admits an interpolated all-lowercase token; only exact-value
# membership is fail-closed across all three ways the engine emits a stage
# (compile-time literal, format!, and variable-bound). A stage not listed here
# is dropped by omission — including the one interpolated stage
# (household_claws.{stage_suffix}.peer_rejected) and the variable-bound stages.
#
# Provenance: generated + hand-minimized from the pinned engine source
# theyos@3145e6fac872b8bd85537f8630380c7444191be7 (refs/tags/v0.1.32, the source
# the shipped 0.1.32 engine asset is attested to; tree
# 055eb919574ec071c61aaef712c68e5a9c770992).
#
# Moved from v0.1.31 on 2026-09-09 and NOT grown. All twenty-three tokens were
# re-verified present as compile-time literals in the v0.1.32 tree — grepped
# against the checked-out tag, not assumed — and none were dropped. Nothing was
# added: the supervisor-from-the-engine-file, the Mac Host sessions in the
# supervisor and the `accessibility` subcommand emit no `stage` token, which
# was checked rather than presumed.
#
# Moved from v0.1.31's predecessor on 2026-09-07 and NOT grown. All twenty-three
# tokens were re-verified present as compile-time literals in the v0.1.31 tree —
# grepped against the checked-out tag, not assumed — and none were dropped.
# Nothing was added: the PTY supervisor this release ships emits no `stage`
# token at all, which was checked rather than presumed. An allowlist that grows
# with every release stops being a closed list; this one only moves when the
# engine actually says something new.
#
# Moved from v0.1.29 on 2026-09-06. All twenty tokens that were listed were
# re-verified present as compile-time literals in the v0.1.30 tree — grepped
# against the checked-out tag, not assumed — and none were dropped. Three were
# ADDED, all three literals in `bonjour_publisher.rs`:
#
#   bonjour.published     the home IS being advertised, and on which interface
#   bonjour.reconciled    the advert followed the window opening or closing
#   bonjour.unregistered  the advert was withdrawn when the window closed
#
# They answer the one question this release creates. Before 0.1.30 the advert
# was decided once at startup: `bonjour.skipped` at 13:51:51 on 2026-09-06,
# then the window opened ten times with nothing announced, and the phone had no
# way to find the Mac. Someone debugging that needs to know whether the home is
# on the air; with these dropped by omission, the diagnostic would say nothing
# about the exact thing that broke. The other twenty-one bonjour and
# household_listener stages in v0.1.30 — shutdown, lag, channel-closed — stay
# out: this list is minimal on purpose, and they describe the publisher's
# internals rather than what a person can act on. Every token below was
# re-verified present as a compile-time literal in that tree when the pin
# moved from 0.1.28 — measured by grepping the checked-out tag, not assumed.
# `pair_machine.window_opened` was dropped in that pass: it is emitted by
# nothing in 0.1.29, and grepping v0.1.28 shows it was emitted by nothing there
# either, so the "verified present" sentence above had never been true of it.
# Four stages were added, all four literals in the new
# `local_network_visibility` module — the routes the Add iPhone sheet calls to
# put the home on the Wi-Fi, whose diagnostics would otherwise be dropped by
# omission on the one path a person is most likely to need explained.
# One token was dropped in the process:
# `macos_local_registration.listener_unavailable`, which is emitted by nothing
# in 0.1.28 and was emitted by nothing in 0.1.27 either, so the "verified
# present" sentence above had not been true of it since it was written. The
# stage the listener actually emits on that path is
# `macos_local_registration.serve_failed`, already listed below. Scope: the
# initialize/bootstrap/bonjour/long-poll path that carries the initialize
# failure, plus the progress markers needed to locate where it fell. Regenerate
# and re-review if the pin moves. Lines starting with '#' and blank lines are
# ignored.
#
# ── failure tokens (any may BE the initialize/long-poll networkDrop cause) ──
bootstrap.initialize_failed

bootstrap.endpoint.bind_failed

owner_events.long_poll.rejected
household_listener.serve_failed
